% Paragraph purpose: Name the models, the task grid, and how the development panels of the large-corpus runs relate to it.
We fine-tune Qwen3-VL-8B-Instruct \citep{bai2025qwen3vl} (revision 0c351dd0) with low-rank adaptation (LoRA) \citep{hu2022lora} and repeat two algorithms on a second backbone, InternVL3.5-8B \citep{wang2025internvl35}. The main grid, which we call the expanded baseline, covers 24 tasks from 12 PDDL domains, and each of its 12 cells pairs one algorithm with one observation type. The large-corpus runs described below were evaluated on separate development panels, which differ from the main grid in tasks and size (Appendix~\ref{app:data-splits}).

% Paragraph purpose: State the single main training recipe and frame the large-corpus development runs as a data-cost probe, not a matched-size comparison.

To probe how much data BFS and BFWS need, we also report earlier large-corpus development runs. BFS trained on 12,994 records for three epochs and was evaluated on 15 development tasks. BFWS trained on 47,780 records for two epochs and was evaluated on a different 15-task panel. A visual run trained all four algorithms on 43,876 records for two epochs and was evaluated on 42 task groups. These runs differ from the main grid in data, schedule, and panel, so they indicate the data cost and are not a matched-size comparison.

% Paragraph purpose: Define the three controls, state plainly that random-valid reads the runtime's valid-operation list and is a validity bound, and say once why it matches the exact reference in the additive cells.
Three controls frame each learned cell. The pretrained base runs without an adapter. The exact reference runs the declared algorithm in the runtime and reaches the goal on every main-grid task. Random-valid is oracle-assisted: at each step it reads the runtime's list of valid operations and picks one uniformly at random. It therefore bounds what validity alone achieves and is not a competing method. In the additive cells, the runtime supplies every candidate and orders the frontier itself, so every valid submission order yields the same search and random-valid necessarily matches the exact reference (Appendix~\ref{sec:results-identity}).

% Paragraph purpose: Define success, the budget, replay, and the statistics.
An episode succeeds when it reaches the goal with every step valid and within its budget. Budgets count decisions and charge invalid operations. Adapters may use twice the exact reference's decision count, and the pretrained base is priced at one call. An episode counts only after independent replay. Contrasts use a paired whole-instance bootstrap (Appendix~\ref{app:statistics}).

% Paragraph purpose: List the four analyses that follow the main grid, with their scope.
Four analyses follow the main grid. An observation-corruption suite shuffles or masks the text, or blanks or degrades the images, in the additive adapters' observations at test time (Appendix~\ref{app:results-corruption}). Robustness variants apply five families of task changes to the additive adapters: object renaming, name compression, scene restyling, scale-up, and shifted initial states. Transfer evaluates the main-grid adapters on FOLIO \citep{han2022folio} (200 items), GSM8K \citep{cobbe2021gsm8k} (200), and HumanEval \citep{chen2021humaneval} (164), using McNemar tests \citep{mcnemar1947note} against the base with Holm correction \citep{holm1979simple}. The second backbone reruns BFS and greedy best-first search on a 12-task panel.
