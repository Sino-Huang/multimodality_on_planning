\section{Experimental Design}
\label{sec:design}

% Paragraph purpose: Name the model, the 12 domains shared by both levels, and the whole-task split rule; setup detail (revision, LoRA hyperparameters, ledgers) lives in Appendix app:data-splits.
We fine-tune Qwen3-VL-8B-Instruct \citep{bai2025qwen3vl} with low-rank adaptation (LoRA) \citep{hu2022lora}, training one adapter per algorithm and, for execution, per observation type. The small-set execution grid and the node-choice study use 12 PDDL domains: 15-puzzle, Blocksworld, Depot, Driverlog, Elevators, Ferry, Grid, Gripper, Logistics, Storage, Towers of Hanoi, and Visitall. The larger execution runs draw from these and three more, FreeCell, Snake and Sokoban. State images come from Planimation \citep{chen2020planimation}, which draws a PDDL state through an animation profile written once per domain; we render each state from the task's own PDDL, without planning, and downscale it to an unlabelled 128-pixel scene, so each domain keeps its own visual vocabulary (Figure~\ref{fig:domains}a). The larger visual runs used an earlier render of the same kind that keeps object names in some domains (Appendix~\ref{app:data-splits}). Every split is by whole task, so no evaluation task contributes a training record, and every evaluation episode counts only after an independent replay confirms it (Appendix~\ref{app:data-splits}).

% Paragraph purpose: Execution level: the small-set grid (BFS, BFWS x three observation types) and the larger development runs that show how much data suffices; state once that they are not a matched comparison; define the execution budget.
\paragraph{Executing BFS and BFWS.} Each small-set adapter trains for one epoch on 512 reference operations, at training seed 17, for each of BFS and BFWS under each of the three observation types. The six adapters are evaluated on 24 tasks, two from each domain. To test whether more data suffices, we also report larger training runs. From text observations, BFS trained on 12,994 operations for three epochs at five training seeds and BFWS on 47,780 for two, and from visual observations BFS trained on 11,911 and BFWS on 14,225 for two epochs. Each larger run was evaluated on its own 15-task panel, so these runs differ from the small-set grid in tasks, schedule and panel; they show that enough data suffices, not how much is needed, and they do not form a matched comparison. An execution episode may use twice the reference's number of operations.

% Paragraph purpose: Search-control level: the node-choice corpus, augmentation and seeds; the two held-out panels and what the screen on the first one selects; the budget and the reported success measure.
\paragraph{Choosing the next node for GBFS and WA*.} Each node-choice adapter trains on 2,048 reference choices, taken from 236 training tasks across all 12 domains and restricted to menus with at least two open nodes. Every record appears twice with the menu in different orders, so the position of a label carries no signal, and each adapter trains for one epoch at each of three training seeds (17, 29 and 71). Evaluation uses two held-out panels of fresh tasks whose optimal plans have 8 to 20 steps. The first panel (held-out 1, 11 tasks from 8 domains) keeps only tasks on which random choice reaches the goal in 1 to 9 of 10 screening runs, so that random choice on these tasks is neither hopeless nor sufficient. The second (held-out 2, 12 tasks from 7 domains) drops this screen. A third, 12-task panel from 7 domains enters only the pooled analysis and the comparison with the untrained model. An episode may use twice the reference's number of expansions, and we report success within this budget, averaged over the three training seeds; Appendix~\ref{sec:results-choice-frontier} adds the area under the solve-versus-budget curve.

% Paragraph purpose: Define the three controls at both levels, say plainly that random-valid reads the runtime's valid set and is a bound, not a method.
% \paragraph{Controls.} Three controls frame each learned result. The pretrained base runs the same loop without fine-tuning. The exact reference is the algorithm itself, run by the runtime, and it solves every evaluation task at both levels. Random-valid picks uniformly among the valid decisions at each step: among the valid operations when executing, and among the open nodes when choosing. It is averaged over five seeds for node choice and the larger runs, and uses one seed on the small set. It reads the runtime's valid set, so it bounds what validity alone achieves and is not a competing method. For node choice, the base model also receives one sentence stating the output format and asking for the open node whose scene looks closest to the goal, and it is evaluated on the third panel and held-out 1.

\paragraph{Transfer and statistics.} To test whether the learned search carries beyond planning, we evaluate the six small-set execution adapters and the base on FOLIO \citep{han2022folio} (200 items), GSM8K \citep{cobbe2021gsm8k} (200), and HumanEval \citep{chen2021humaneval} (164). Execution contrasts use a bootstrap over whole tasks, and node-choice contrasts resample tasks with the three seeds averaged inside each draw (Appendix~\ref{app:statistics}).
