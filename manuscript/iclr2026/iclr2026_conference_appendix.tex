\section{Operation Schemas}
\label{appendix}

% Paragraph purpose: Introduce the typed operation vocabulary and the operand ownership rule that governs all schemas.
Each declared algorithm defines a vocabulary of operation types $\tau$. A policy emission $u_t = (\tau_t, \theta_t)$ pairs a type from that vocabulary with an operand vector $\theta_t$ carrying every exploration-determining argument. The runtime rejects any emission whose type falls outside the declared vocabulary or whose operand vector omits a required field. Every operand that determines exploration must originate from the policy (Section~\ref{sec:policy}).

% Paragraph purpose: Describe the BFS operation schema at the level pinned by the sources.
\paragraph{BFS.}
The primary operation is node expansion. Its operands name the source state (the current frontier head), the grounded successors selected for insertion, the action producing each successor, and the enqueue position for each. The runtime checks that the named source matches the FIFO frontier head, that each successor results from an applicable grounded action in the source state, that the successor is unvisited, and that each insertion targets the FIFO tail. A goal-test operation names the state to test. The BFS pilot corpus (\#111) exposes exact grounded successor candidates and full visited membership at each step.
% TODO: The exact BFS operation-type enumeration and per-field schema (field
% names, types, serialization format) are not recorded in any audited
% document; pin them from the codebase before release.

% Paragraph purpose: Describe the BFWS operation schema at the level pinned by the sources.
\paragraph{BFWS (complete unpruned).}
Expansion operands carry the novelty value and goal-count priority of the source state alongside the fields above. Insertion operands carry each candidate's duplicate membership, novelty, and priority. The runtime checks that the selected source has the declared best priority, that duplicate membership is correctly reported, and that insertions follow the declared ordering. The BFWS corpus (\#57--\#58) exposes candidate duplicate, novelty, priority, insertion, and enqueue facts at every training observation.
% TODO: The exact BFWS operation-type enumeration, per-field schema, and the
% precise novelty computation (tuple arity, width parameter) are not pinned
% in audited documents; record them before release.

% Paragraph purpose: Describe the additive best-first operation schema at the level pinned by the sources.
\paragraph{Additive best-first.}
Operands carry the source state's accumulated path cost $g$, heuristic estimate $h_{\rm add}$, and composite value $f = g + w \cdot h_{\rm add}$ with $w = 3$ for the weighted variant, or $f = h_{\rm add}$ for the greedy variant. Insertion operands carry per-successor $g$, $h_{\rm add}$, and $f$. The runtime checks that the expanded state has the minimum $f$ in the frontier under the declared tie-breaking rule and that all arithmetic is consistent.
% TODO: Per-field schema for additive best-first operation types and the exact
% tie-breaking rule are not pinned in audited sources; see Section~B.

% Paragraph purpose: State the validity preconditions as an ordered rejection hierarchy.
\paragraph{Validity preconditions.}
An emission passes through a fixed sequence of checks. Failure at any step rejects the emission with the corresponding kind and terminates the episode. The checks, in order:

\begin{enumerate}[leftmargin=*, itemsep=1pt, parsep=1pt]
\item \textbf{Parse.} The raw output must parse into a well-formed Typed Search Operation with a recognized type and complete operand vector. Failure: \texttt{malformed\_output}.
\item \textbf{Source identity.} The named source state must match the state the algorithm expects. Failure: \texttt{source\_state\_mismatch}.
\item \textbf{Action applicability.} Every grounded action in the operands must be applicable in the source state. Failure: \texttt{inapplicable\_grounded\_action}.
\item \textbf{Successor schema.} Any named successor state must satisfy the domain schema. Failure: \texttt{schema}.
\item \textbf{Successor effects.} The named successor must match the declared effects of the applied action. Failure: \texttt{effect}.
\item \textbf{Static context.} Referenced predicates, objects, and constants must be consistent with the task instance. Failure: \texttt{static\_context}.
\item \textbf{Frontier discipline.} The frontier manipulation must respect the declared ordering (FIFO for BFS, priority for BFWS, $f$-order for additive best-first). Failure: \texttt{invalid\_frontier\_operation}.
\item \textbf{Algorithm invariant.} Any remaining algorithm-specific constraint not covered above. Failure: \texttt{other\_invariant\_violation}.
\end{enumerate}

The two broad categories are \emph{malformed-output} rejections, where the emission never reaches the operation checker, and \emph{post-parse rejections}, where the emission parses but fails a runtime check. The oracle-assisted random-valid control, which emits only runtime-accepted operations, has a single failure kind: \texttt{expansion\_budget\_exhausted}, recorded when the frozen episode budget runs out before a goal is reached.

\section{Algorithm Invariant Definitions}

% Paragraph purpose: State each active algorithm's invariants as checked by the runtime.
The Trusted Search Runtime checks the following invariants on every operation. Stepwise validity and invariant compliance do not establish termination, completeness, optimality, or episode success (Section~\ref{sec:policy}).

% Paragraph purpose: BFS invariant.
\paragraph{BFS.}
The frontier is a FIFO queue. Every expansion must select the queue head as its source. Every insertion must target the queue tail. A state already in the visited set must not be re-inserted. This invariant is sufficient for completeness in finite state spaces with unit-cost transitions.

% Paragraph purpose: BFWS invariant.
\paragraph{BFWS (complete unpruned).}
The frontier is a priority queue ordered first by novelty rank (lower is better), then by goal count among states with equal novelty. No generated successor is pruned. A successor whose state already appears in the frontier or visited set is not re-inserted.
% TODO: The exact novelty definition (tuple arity, width parameter, and
% tie-breaking within equal novelty and equal goal count) is not pinned in
% any audited document. Record the precise rule before release.

% Paragraph purpose: Weighted additive best-first invariant.
\paragraph{Additive best-first, weighted ($w = 3$).}
The frontier is a priority queue ordered by $f(s) = g(s) + 3 \cdot h_{\rm add}(s)$, where $g(s)$ is the accumulated path cost and $h_{\rm add}(s)$ is the additive heuristic. The expanded state must have the minimum $f$ in the frontier. When a successor is generated with a lower $g$ than an existing frontier entry for the same state, the entry is reopened with the improved cost.
% TODO: Tie-breaking among equal-f states is not pinned in any audited source.
% Record the exact rule before release.

% Paragraph purpose: Greedy additive best-first invariant.
\paragraph{Additive best-first, greedy.}
The frontier is ordered by $h_{\rm add}(s)$ alone, with no path-cost component. The expanded state must have the minimum $h_{\rm add}$. Reopen and duplicate rules follow the same convention as the weighted variant.

\section{Trusted Search Runtime}

% Paragraph purpose: State the three guarantees of the runtime.
The runtime provides three guarantees that hold across all declared algorithms.

\begin{enumerate}[leftmargin=*, itemsep=1pt, parsep=1pt]
\item \textbf{No-repair property.} The runtime validates, applies, persists to Search Memory, or rejects each emission. It never chooses omitted operands, reorders candidates, silently repairs an invalid emission, or substitutes a default search decision.
\item \textbf{Reject-and-terminate.} On the first rejected emission the episode terminates with the rejection kind recorded. There is no retry path.
\item \textbf{Replay determinism.} Replaying the raw emissions $u_{1:T}$ against the same task instance and the same initial Search Memory reproduces the explored trace. Any step whose outcome depends on runtime repair would violate this property.
\end{enumerate}

% Paragraph purpose: Present the per-step and episode-level pseudocode using tabbing.
The procedures below specify the per-step check and the episode loop. No \texttt{algorithm} package is loaded. The listing uses \LaTeX\ tabbing.

\begin{quote}
\small
\begin{tabbing}
\hspace{1.5em}\=\hspace{1.5em}\=\hspace{1.5em}\=\kill
\textbf{procedure} \textsc{Step}($u_t$, $M_{t-1}$, $A$, $x$) \\
\> \textit{// Phase 1: Parse the raw emission} \\
\> \textbf{if} $u_t$ does not parse as $(\tau, \theta)$ with $\tau \in \mathrm{vocab}(A)$ \textbf{then} \\
\>\> \textbf{return} \textsc{Reject}(\texttt{malformed\_output}) \\[2pt]
\> \textit{// Phase 2: Validate source identity} \\
\> \textbf{if} $\theta.\mathrm{source} \neq \mathrm{expected}(A, M_{t-1})$ \textbf{then} \\
\>\> \textbf{return} \textsc{Reject}(\texttt{source\_state\_mismatch}) \\[2pt]
\> \textit{// Phase 3: Validate operands against the task and state} \\
\> \textbf{for each} grounded action $a$ named in $\theta$ \textbf{do} \\
\>\> \textbf{if} $a$ is not applicable in $\theta.\mathrm{source}$ under $x.D$ \textbf{then} \\
\>\>\> \textbf{return} \textsc{Reject}(\texttt{inapplicable\_grounded\_action}) \\
\> \textbf{for each} successor state $s'$ named in $\theta$ \textbf{do} \\
\>\> \textbf{if} $s'$ violates the domain schema \textbf{then} \\
\>\>\> \textbf{return} \textsc{Reject}(\texttt{schema}) \\
\>\> \textbf{if} $s' \neq \mathrm{effects}(a, \theta.\mathrm{source})$ \textbf{then} \\
\>\>\> \textbf{return} \textsc{Reject}(\texttt{effect}) \\
\> \textbf{if} any static-context reference in $\theta$ is inconsistent with $x$ \textbf{then} \\
\>\> \textbf{return} \textsc{Reject}(\texttt{static\_context}) \\[2pt]
\> \textit{// Phase 4: Check Algorithm Invariant} \\
\> \textbf{if} frontier discipline of $A$ is violated by $(\tau, \theta, M_{t-1})$ \textbf{then} \\
\>\> \textbf{return} \textsc{Reject}(\texttt{invalid\_frontier\_operation}) \\
\> \textbf{if} any other invariant of $A$ is violated \textbf{then} \\
\>\> \textbf{return} \textsc{Reject}(\texttt{other\_invariant\_violation}) \\[2pt]
\> \textit{// Phase 5: Apply and persist} \\
\> $M_t \leftarrow \mathrm{apply}(\tau, \theta, M_{t-1})$ \\
\> \textbf{return} \textsc{Accept}($M_t$)
\end{tabbing}
\end{quote}

\begin{quote}
\small
\begin{tabbing}
\hspace{1.5em}\=\hspace{1.5em}\=\hspace{1.5em}\=\kill
\textbf{procedure} \textsc{Episode}($x$, $A$, $\phi_m$, $B$) \\
\> $M_0 \leftarrow \mathrm{InitSearchMemory}(A, x)$ \\
\> \textbf{for} $t = 1, 2, \ldots, B$ \textbf{do} \\
\>\> $o_t \leftarrow \phi_m\bigl(c_t(x, M_{t-1})\bigr)$ \hspace{2em} \textit{// build observation} \\
\>\> $u_t \leftarrow \pi(o_t)$ \hspace{6.4em} \textit{// policy emission} \\
\>\> $r \leftarrow$ \textsc{Step}($u_t$, $M_{t-1}$, $A$, $x$) \\
\>\> \textbf{if} $r$ is \textsc{Reject}(\textit{kind}) \textbf{then} \\
\>\>\> \textbf{return} $(t, \textsc{Fail}, \textit{kind})$ \\
\>\> $M_t \leftarrow r.M$ \\
\>\> \textbf{if} $\mathrm{GoalTest}(M_t, x.G) = \textsc{True}$ \textbf{then} \\
\>\>\> \textbf{return} $(t, \textsc{Success})$ \\
\> \textbf{return} $(B, \textsc{Fail}, \texttt{expansion\_budget\_exhausted})$
\end{tabbing}
\end{quote}

% Paragraph purpose: Note budget enforcement.
Each call to \textsc{Step} consumes one unit of the frozen episode budget $B$, whether the emission is accepted or rejected. Invalid operations are therefore charged to the budget (Section~\ref{sec:design}).

\section{Statistics}

% Paragraph purpose: State the default contrast procedure.
\paragraph{Default contrast procedure.}
Contrasts are paired by whole task instance. Paired differences use a bootstrap with 10,000 resamples at seed 1729 and 95\% percentile intervals. Under one training seed and panels of 24 or fewer instances, these intervals are descriptive bounds. They do not support broad superiority claims.

% Paragraph purpose: Pin the BFWS gate bound to its two-sided percentile interval.
The BFWS gate (\#59) used confidence level 0.95 with 10,000 paired whole-instance resamples (bootstrap seed 1729). Its reported lower bound is the 0.025 quantile, i.e., the lower endpoint of a two-sided 95\% percentile interval.

% Paragraph purpose: State the tiny-strata rule.
\paragraph{Tiny-strata rule.}
Strata with fewer than 8 episodes are reported as descriptive only. No intervals are computed over such strata. They are listed explicitly and never silently pooled or dropped.

% Paragraph purpose: State the transfer test procedure.
\paragraph{Transfer tests.}

\section{Modality Adapters and Observation Contract}

% Paragraph purpose: Define each adapter and the decision-sufficiency requirement.
Three fixed Modality Observation adapters are declared. Each maps a decision context $c_t$ (the canonical task context plus the decision-relevant view of Search Memory $M_t$) to an observation $o_t = \phi_m(c_t)$ presented to the policy. The adapter is fixed for an entire training or evaluation cell. The adapter contract requires decision sufficiency: $o_t$ must expose every fact the exact teacher uses to resolve step $t$ under the declared algorithm.

% Paragraph purpose: text-state adapter.
\paragraph{text-state.}
The state, goal, and search context are serialized as a compact relational representation. Object identities, predicate names, and all Search Memory contents (frontier, visited set, algorithm-specific state) appear as structured text.

% Paragraph purpose: visual-state adapter.
\paragraph{visual-state.}
The state and goal are rendered as a pair of 128$\times$128 pixel images: a rendered state image and a partial-goal constraint image. Object labels are not embedded in the rendered image. Search Memory contents and the grounded candidate list remain in the textual serialization, even in this adapter. This is the published frozen \texttt{visual-state} arm that the native arms below are compared against.

% Paragraph purpose: multimodal-state adapter.
\paragraph{multimodal-state.}
The observation combines the text-state serialization and the visual-state rendered images. The policy receives the relational text and the image pair jointly.

% Paragraph purpose: Record the executed native-arms v2 adapters and how they reduce the textual payload.
\paragraph{Native image-only arms (\#129).}
Two further adapters executed under the native-arms v2 contract. \texttt{visual-nomem-state} keeps only the static task interface and the grounded, unscored candidate menu as text, and carries state facts in the current rendered scene alone. \texttt{visual-seq-state} adds up to $K{=}8$ rendered history frames, each labelled with its absolute path depth. Neither receives textual Search Memory, accepted deltas, $g$/$h$/priority scalars, candidate scores, or membership flags.
% Evidence: docs/experiments/native-arms/native-arms-design.md (removed and retained keys, history frame labels);
% configs/experiments/native-arms/native-arms-v2-protocol.json history_window.

% Paragraph purpose: State the text-scaffold caveat.
\paragraph{Text-scaffold caveat.}
Search Memory contents and the candidate list are serialized as structured text in all three declared adapters, including visual-state. Rendered images carry the planning state and goal visuals, but search bookkeeping (frontier, visited set, novelty counters, candidate list) always travels through the text channel. The observation-corruption suite (\#126) confirms this empirically: corrupting the text channel drops success by up to $-0.944$, while corrupting the visual channel moves success by at most $-0.111$ with intervals that include zero.

% Paragraph purpose: State what the executed native arms changed in the text-scaffold caveat.
The native arms narrow this caveat to the candidate menu. With the textual bookkeeping and scalars removed, both arms solve 18/18 clean tasks with zero invalid operations, and blanking or degrading every image of the seq arm gives a corrupted-minus-clean contrast of $0.000$ $[0.000, 0.000]$. The remaining text channel, the grounded unscored menu, is the channel these policies use. Menu manipulation then shows the policies read menu content without checking applicability against the scene. The caveat therefore still holds for every adapter that presents the menu, and no executed adapter isolates an image-only decision channel.
% Evidence: docs/experiments/native-arms/issue-129-closeout.md (18/18 per arm, zero invalid, corruption 0.000 [0.000, 0.000],
% menu-leak interpretation); docs/experiments/native-arms/issue-130-closeout.md R1. Same numbers as Section~\ref{sec:results}.

% Paragraph purpose: State information-loss and parity boundaries.
\paragraph{Information-loss boundaries.}
The 128-pixel unlabelled rendered views can lose symbolic identities. The P3 name-compression family in the generalization-v2 suite is information-lossy: 24/24 variants are text-lossy, 18/24 are multimodal-lossy, and 0/24 are visual-lossy. Modality matching between training and evaluation ensures identical observation format, not information parity. Static-context and goal fields of the observation contain text in every adapter. The available evidence does not establish semantic parity across adapters or an intrinsic modality effect.

\section{Retained-Infrastructure Feasibility Notes}

% Paragraph purpose: Scope the section: feasibility evidence, not efficacy.
The terms below describe verified infrastructure components that support corpus generation, evaluation, and evidence production. They constitute feasibility evidence for the runtime and rendering pipeline. They cannot support a Search Process Policy efficacy claim.

% Paragraph purpose: Define the plan pipeline terms.
\paragraph{Plan pipeline.}
\textbf{Plan Submission} transmits a supplied plan from the project adapter to a planning or rendering backend. \textbf{Plan Interpretation} converts the submitted plan into the backend's ordered action representation. An \textbf{Action Sequence} is the canonical identity of a supplied plan as a normalized, ordered sequence of grounded action predicates. Casing and whitespace are not part of its identity.

% Paragraph purpose: Define the rendering pipeline terms.
\paragraph{Rendering pipeline.}
\textbf{Render Production} creates a visualisation output and its rendered image for a planning state. \textbf{Render Validation} confirms that the produced visualisation and image satisfy declared structural and semantic checks. \textbf{Plan Provenance} links a produced visualisation to the exact supplied plan that the backend interpreted.

% Paragraph purpose: Define the certification and evidence terms.
\paragraph{Certification and evidence.}
\textbf{Integration Certification} is the finding that Plan Submission, Plan Interpretation, Plan Provenance, Render Production, Render Validation, and required execution-isolation checks all passed. An \textbf{Attempt} is one authorized, immutable execution with its own identity and retained outcome, whether successful or not. An \textbf{Evidence Bundle} is the self-contained records from an Attempt that allow an independent reproducer to verify its claims offline. Issue \#110 supplies deterministic compact delta/event evidence with semantic replay while preserving search semantics, serving the replay-determinism requirement of the Trusted Search Runtime.

\paragraph{Historical terms.}
Planning Certificate, Joint Action-and-Certificate SFT, Adaptive Scaffolding, Support Route, Live Memory, Verified Joint Step, and Route Label are historical CGAS terms. They describe retained infrastructure internals. They cannot support any current Search Process Policy efficacy claim and are not referenced elsewhere in this manuscript.


\section{Choice-Frontier Contract and Comparator Selectors}

% Paragraph purpose: Specify the choice-frontier menu and observation payload at the level the design pins.
\paragraph{Menu and observation.}
At each decision the runtime exposes the live frontier as an unscored menu of opaque labels $c_0, \ldots, c_K$. Labels are assigned after a seeded Fisher--Yates permutation of the generation-serial member order, with a per-decision seed derived from master seed 51131 and a hash of the member state identifiers, so a label carries no positional information. The observation holds static task-context pages, the unlabelled 128px initial-state scene, one unlabelled 128px scene per frontier state in menu order, and the partial-goal pages. Its text payload carries only the algorithm name, the label list, the representation tag, the schema version, and the frozen legend. A leak check fails closed on any forbidden key marker.
% Evidence: docs/experiments/choice-frontier/issue-132-design.md section 2 (menu, seed rule, payload, assert_no_text_leak).

% Paragraph purpose: Specify the output contract, validation, and termination rules.
\paragraph{Output and validation.}
The policy emits canonical JSON with the single key \texttt{expand\_choice} and a label value. The runtime rejects malformed JSON, a wrong key set, a non-string label, a label not offered by the pending menu, and a label bound to a non-live member. The first rejection ends the episode as \texttt{deterministic\_invalid\_operation}. Other terminations are \texttt{goal\_reached}, \texttt{frontier\_exhausted}, \texttt{decision\_budget\_exhausted}, and \texttt{expansion\_budget\_exhausted}.
% Evidence: issue-132-design.md section 2 (output contract, rejections, termination reasons).

% Paragraph purpose: Specify the atomic expansion, goal-at-selection, and budget accounting.
\paragraph{Expansion and budget.}
On acceptance the runtime removes the chosen member from the frontier and expands it atomically. Candidate generation, serial assignment, admission, duplicate detection, reopening, and expansion bookkeeping are inherited unchanged from the frozen additive best-first controller, which is not modified. Per-candidate admissions are runtime-internal, so one submitted choice is one decision. Selecting a member that satisfies the goal solves the task without an expansion and without budget charge, so the exact episode takes its reference expansion count plus one decisions. Decision and expansion caps both equal 2$\times$ the reference expansion count.
% Evidence: issue-132-design.md section 2 (expand_member, inherited BestFirstController internals, goal at selection,
% decision_cap = expansion_cap = 2 x reference_expansions); issue-132-closeout.md Erratum items 1 and 5.

% Paragraph purpose: Specify the corpus derivation rule and its gates, with the pinned counts.
\paragraph{Corpus derivation.}
The corpus replays the frozen paired-phase exact traces through the new contract on CPU. The frozen matched-modalities membership indexes enumeration-contract decisions. Each such decision maps to the expansion whose candidate set it submitted into, unique (task, expansion) pairs in first-occurrence order form the base set, and a round-robin over the frozen task order tops the set up to 512 training records per algorithm. Diagnostics are the unique expansions of the frozen diagnostic identifiers, with no top-up. The teacher target is the label bound to the heap head. Five fail-closed gates run before training. They check expansion-for-expansion agreement with the stored exact traces, a token budget of measured input plus 384 within 32,768, the text-leak check, image resolution, and identity with the frozen membership. The pinned preparation report records 29 tasks, 1,046 records (512 training and 11 diagnostic per algorithm), 3,544 scenes, and 58 episodes re-derived bit-exact, with outcome PASS. The smoke gate accepted 40/40 model calls.

% Paragraph purpose: Specify how the #133 selectors run inside the same contract and what their replay covers.
\paragraph{Comparator selectors (\#133).}
Each selector's choice is mapped back to the menu binding, and every candidate still enters through the additive admission path. Frontier admission, duplicate detection, $h_{\rm add}$ computation, reopening, and serial ordering therefore stay additive for \texttt{bfs-order} and novelty-first selection alike. The novelty features of novelty-first selection are positive PDDL state atoms, and its seen-feature sets advance only when a state is expanded, including the initial expansion. Each new episode is re-run against an independently constructed PDDL authority, which checks menus, decisions, admissions, and result dictionaries. Selector episodes replay the model input, menu, actions, admissions, and budget, but they neither generate nor replay image bindings. The optimal costs $C^*$ come from one offline shortest-plan computation per task with replay-verified plans, and the native four-algorithm reference costs are recorded separately from the zoo.

% Paragraph purpose: Specify the metric computations the protocol pins beyond the Experimental Design summary.
\paragraph{Metric computation (\#133).}
Under M1 an episode solves at multiplier $m$ when its first goal selection occurs within $\lfloor m R_t \rfloor$ decisions with at most $\lfloor m R_t \rfloor$ preceding expansions, where $R_t$ is the additive exact-reference expansion count. Unsolved 2$\times$ runs count as failures at every $m$, and the same prefix truncation applies to every arm. Task and algorithm weights are equal. M2 also has a censored form, in which failures are right-censored at the budget rather than assigned a fictitious expansion count. M3 counts transitions along the selected goal state's trusted predecessor chain and is undefined, never imputed, for unsolved episodes. M4 measures agreement with the current additive heap head over decisions with at least two live choices, against a chance rate equal to the decision-weighted mean of $1/K$. M5 restricts to tasks where the mean 2$\times$ random-valid solve indicator lies strictly between 0 and 1.
