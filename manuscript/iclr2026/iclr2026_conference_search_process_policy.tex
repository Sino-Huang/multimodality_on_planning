\section{Learning Search from Traces}
\label{sec:policy}

% Paragraph purpose: Overview of the problem setting before notation: the runtime holds the search, the VLM writes the algorithm's next decision, the runtime accepts only what the algorithm would do; the two levels split by algorithm.
We cast learning to search as imitation of an algorithm's own decisions. A runtime holds the search memory of a declared algorithm. At every step the VLM reads an observation of that memory and writes the algorithm's next decision, and the runtime applies the decision only if the algorithm would make it (Figure~\ref{fig:contracts}). What the VLM must learn depends on the level. When it executes BFS or BFWS, it keeps the algorithm's bookkeeping: which successors enter the open list, where each one goes, and when the expansion ends, so the node expanded next is the head of an open list that its own operations built. When it controls GBFS or WA*, it learns the algorithm's preference among open nodes: it must pick the node the heuristic would pick, from images alone and without the heuristic values. At both levels the runtime generates the successors and the values the keys need and checks each decision; the VLM writes every decision itself.

% Paragraph purpose: Define the planning task formally (grounded STRIPS from PDDL, unit costs).
\paragraph{Planning tasks.} A task is a grounded STRIPS task $\Pi=\langle F,O,s_I,G\rangle$ obtained from a PDDL domain and problem, with a set of facts $F$, a set of operators $O$, an initial state $s_I\subseteq F$, and a goal $G\subseteq F$. Each operator $o$ has a precondition $\mathit{pre}(o)$, an add list $\mathit{add}(o)$ and a delete list $\mathit{del}(o)$, all subsets of $F$, and unit cost. It is applicable in a state $s$ if $\mathit{pre}(o)\subseteq s$ and leads to $s[o]=(s\setminus\mathit{del}(o))\cup\mathit{add}(o)$. A plan is a sequence of applicable operators from $s_I$ to a state that contains $G$.

% Paragraph purpose: Define the four algorithms as best-first searches with an algorithm-specific ordering key (introducing the placeholder \mathcal{A}); define BFWS novelty and the additive heuristic; state reopening and duplicate rules; then note that the keys fall into two kinds (bookkeeping vs heuristic estimate). What the VLM does at each level is stated in the overview and defined in the two level paragraphs, not repeated here.
\paragraph{Four best-first searches.} All four algorithms are best-first searches: each keeps an open list of generated but unexpanded nodes and always expands the node with the lexicographically smallest key. A search node $n$ holds a state $s(n)$, its path cost $g(n)$, and a generation serial $\sigma(n)$ that counts the nodes generated before it. Writing $\mathcal{A}$ for any one of the four algorithms, its key $\kappa_{\mathcal{A}}(n)$ is
\begin{equation}
\begin{aligned}
\kappa_{\rm BFS}(n) &= \langle \sigma(n) \rangle, &
\kappa_{\rm BFWS}(n) &= \langle w(n),\ \#g(n),\ g(n),\ \sigma(n) \rangle, \\
\kappa_{\rm GBFS}(n) &= \langle h_{\rm add}(n),\ \sigma(n) \rangle, &
\kappa_{\rm WA^*}(n) &= \langle g(n)+3\,h_{\rm add}(n),\ \sigma(n) \rangle.
\end{aligned}
\label{eq:keys}
\end{equation}
BFS therefore expands nodes in the order they were generated. BFWS \citep{lipovetzky2017bestfirst} ranks a node first by its novelty $w(n)$. This is the size of the smallest set of one or two facts that holds in $s(n)$ but in no previously generated state with the same number $\#g(n)=|G\setminus s(n)|$ of unachieved goals, and $w(n)=3$ when no such set exists. Ties go to fewer unachieved goals, then to shallower nodes. Greedy best-first search (GBFS) and weighted A* (WA*) rank nodes by the additive heuristic $h_{\rm add}$ \citep{bonet2001planning}, alone or added to the path cost with weight 3 \citep{hart1968formal,pohl1970heuristic}. WA* reopens a closed node when it finds a cheaper path to it, and GBFS does not. BFS and BFWS never insert a state that has already been generated. The keys fall into two kinds, and our two levels follow them. The keys of BFS and BFWS follow from bookkeeping over the nodes generated so far: a counter, and for BFWS the novelty tables and the goal count. The keys of GBFS and WA* depend on $h_{\rm add}$, an estimate of the distance to the goal computed from the whole task.

% Paragraph purpose: Define what the runtime supplies when the VLM executes BFS or BFWS (the node under expansion, its successors, and their ordering values) and why successors are supplied (operational reasoning is a separate competency, huang2026twodistinct); then the operation the VLM must compose from a candidate (derive vs copy).
\paragraph{Executing BFS and BFWS.} The runtime holds the search memory $M_t$: the open list ordered by $\kappa_{\mathcal{A}}$, the set of visited states, and, for BFWS, the novelty tables. When an expansion starts, the runtime selects the head of the open list, and $n_t$ denotes the node under expansion at step $t$. The runtime also generates the successors of $n_t$ and lists them as candidates $C_t$, one for each operator $o$ applicable in $s(n_t)$, with the successor state $s(n_t)[o]$. Supplying successors keeps the study on search. Judging action applicability and state transitions, which \citet{huang2026twodistinct} identify as operational reasoning, is a planning competency distinct from reasoning over the structure of the state space, so we do not test it here. Each candidate also carries the values that $\mathcal{A}$ uses to place it, all computed by the runtime: a visited flag for BFS, and a duplicate flag, $w$ and $\#g$ for BFWS. The VLM turns one candidate into an operation $a_t$, which inserts it into the open list:
\begin{equation}
a_t = \langle \mathit{src},\, o,\, r,\, p \rangle,
\label{eq:operation}
\end{equation}
where $\mathit{src}$ names $n_t$, $o$ names the candidate, $r$ states whether this step removes $n_t$ from the open list, and $p$ is the candidate's position in it. Under BFS the VLM must work out $r$ and $p$ from the queue, because a new node goes to the back. Under BFWS the candidate supplies $r$ and $p$, and the VLM copies them.

% Paragraph purpose: Define the valid-operation set per algorithm formally, distinguish it from the candidate list, list what makes an output invalid, give the transition, and state that accepted operations are an execution of A.
\paragraph{Validity.} The VLM generates free text, and only some texts are operations that $\mathcal{A}$ would perform. Let $r_t$ indicate whether $n_t$ is still in the open list, $|\mathit{open}_t|$ be the length of the open list, and $\hat r_o, \hat p_o$ be the values that a BFWS candidate carries. The valid operations are
\begin{equation}
\begin{aligned}
V_{\rm BFS}(M_t) &= \{\langle n_t, o, r_t, |\mathit{open}_t|-r_t\rangle : o\in C_t,\ s(n_t)[o] \text{ not visited}\},\\
V_{\rm BFWS}(M_t) &= \{\langle n_t, o, \hat r_o, \hat p_o\rangle : o\in C_t,\ s(n_t)[o] \text{ not a duplicate}\},
\end{aligned}
\label{eq:valid}
\end{equation}
together with a retire operation, which ends the expansion, once no such candidate remains. The candidates name the successors, but they are not the valid operations. An output is invalid when it does not parse, names a node other than $n_t$ or an operator outside $C_t$, inserts a visited or duplicate successor, or gives the wrong $r$ or $p$. The runtime updates
\begin{equation}
M_{t+1} = T_{\mathcal{A}}(M_t, a_t) \quad \text{if } a_t \in V_{\mathcal{A}}(M_t),
\label{eq:transition}
\end{equation}
and otherwise ends the episode without repairing $a_t$. It tests the goal when it selects a node for expansion, and BFWS also tests each generated node. Any sequence of accepted operations is therefore an execution of $\mathcal{A}$: every step the VLM writes must keep the order and bookkeeping of $\mathcal{A}$ (Appendices~\ref{app:invariants} and~\ref{app:runtime}).

% Paragraph purpose: Define the observation function and the three observation types for execution; state that only facts become images while candidates, memory summary and recent operations stay text.
\paragraph{Observations.} When executing BFS or BFWS, the VLM sees $o_t=\phi_m(\Pi, M_t, C_t)$ for an observation type $m\in\{\text{text},\text{visual},\text{multimodal}\}$. The three types differ only in how the facts of the task and the current state reach the model. The text observation lists the objects, the static facts, the initial and current states, and the goal. The visual observation replaces these facts with images: scenes of the initial and current states drawn by the Planimation renderer \citep{chen2020planimation}\footnote{\url{https://github.com/planimation/backend}}, and pages that render the static facts and the goal. The multimodal observation gives both. In every type the candidates $C_t$, a summary of $M_t$ and the last 16 accepted operations stay in text, so only the facts become images.

% Paragraph purpose: Define the search-control level formally for GBFS and WA*: the VLM chooses which open node to expand from an unordered image menu without heuristic values; the runtime does the rest; the reference choice.
\paragraph{Choosing the next node for GBFS and WA*.} For the heuristic searches, the VLM makes the decision that $\kappa_{\mathcal{A}}$ makes in Eq.~(\ref{eq:keys}). When an expansion is due, the runtime shows the open list as an unordered menu: one image of each open node's state, next to images of the initial state, the static facts and the goal, with the labels shuffled at every decision. The menu shows no heuristic values, so the VLM cannot read the order off the observation and must judge from the images which state to expand. It answers with the label of one open node,
\begin{equation}
a_t = \langle \mathit{expand},\, c\rangle, \qquad c \in \mathit{open}_t,
\label{eq:choice}
\end{equation}
and the runtime expands that node: it generates the successors, computes their keys, and inserts them into the open list itself. Any other answer ends the episode. The reference choice is the open node with the smallest key $\kappa_{\mathcal{A}}$. Every valid answer is a legal expansion, so a VLM whose every answer is valid can still exhaust its budget.

% Paragraph purpose: Define the training data at both levels (reference traces from the runtime, replay-checked) and the SFT objective on decision tokens; contrast with a plan target using the ferry numbers.
\paragraph{Training on traces.} On each training task the runtime runs $\mathcal{A}$ itself and records the reference trace $\tau^*=\big((o_1,a^*_1),\dots,(o_T,a^*_T)\big)$: for BFS and BFWS, the operations of an execution that takes the first allowed candidate at every step, and for GBFS and WA*, the reference choice at every expansion. Each trace is replayed and checked before use. Writing $y=(y_1,\dots,y_L)$ for the tokens of the serialized decision $a^*_t$, we fine-tune the VLM $p_\theta$ on the pooled pairs $\mathcal{D}$ with the next-token objective on the decision tokens only:
\begin{equation}
\mathcal{L}(\theta) = -\sum_{(o_t,\,a^*_t)\in\mathcal{D}}\ \sum_{\ell=1}^{L} \log p_\theta\!\left(y_\ell \mid o_t,\, y_{<\ell}\right).
\label{eq:sft}
\end{equation}
A plan target would supervise only the operators on the path from $s_I$ to the goal. The trace also supervises the steps off that path: every candidate inserted and every expansion closed under BFS and BFWS, and every expansion chosen under GBFS and WA*. On the ferry task of Figure~\ref{fig:teaser}a, BFS writes 10 operations for a plan of 4 operators.

% Paragraph purpose: Define inference (greedy decoding, same runtime loop) and the success criterion at each level; budgets live in Section 4.
\paragraph{Inference and success.} At test time the VLM decodes each decision greedily from $o_t$, and the runtime applies it by Eq.~(\ref{eq:transition}) or Eq.~(\ref{eq:choice}). An episode succeeds if the runtime reaches the goal and every decision was valid, within a budget: on the number of operations when executing BFS or BFWS, and on the number of expansions when choosing nodes for GBFS or WA* (Section~\ref{sec:design}). The pretrained VLM runs the same loops without fine-tuning.
