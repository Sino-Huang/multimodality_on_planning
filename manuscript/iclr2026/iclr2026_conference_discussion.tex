\section{Discussion and Limitations}
\label{sec:discussion}

% Paragraph purpose: State what the data-cost result means for planning research (traces as a supervision target alongside plans), give the observed 512-record failure modes (BFS queue bookkeeping, BFWS operation format) with the explanation marked untested, and frame learning them from less data as the first open problem.
For planning research, our results suggest that search traces are a practical supervision target alongside plans. A model trained on traces learns all four algorithms, but at data costs that differ by more than an order of magnitude: 512 records for the additive variants, against 12,994 and 47,780 records in development runs for BFS and BFWS (Section~\ref{sec:results-data-cost}). The 512-record failures suggest an untested explanation. An additive step only names a listed candidate, and the runtime computes every value that orders the frontier. BFS adapters emit well-formed steps that name a listed successor but get the queue bookkeeping wrong: the back-of-queue position or the head-removal flag. Every BFWS adapter failure is instead a malformed first operation, so the model apparently must first learn the larger BFWS operation and observation format, with more fields and indexed arguments, before its bookkeeping matters. Learning these formats and this bookkeeping from less data is the first open problem.

% Paragraph purpose: State what the observation-channel result means (the trained controllers read the text serialization, bounded by the text-supplied candidate list) and frame the image channel as the second open problem, with the appendix choice-frontier study as a first measured step.
The trained controllers read the textual serialization. For the additive adapters, shuffling the text collapses success, while blanking or degrading the images barely changes it (Section~\ref{sec:results-modality}). This does not show that images are useless in principle, because in every observation type the candidate list stays in text and only state facts become images. Making the image channel carry the decision is the second open problem. An appendix study lets the model pick which frontier state to expand from rendered scenes alone (Appendix~\ref{sec:results-choice-frontier}). On that study's solve-versus-budget score, the trained model reaches 0.306, above 0.021 for random choice but far below 0.875 for exact search.

The robustness and transfer results are narrower. The heuristic best-first adapters keep solving tasks under renaming, name compression, restyling, and scale-up, and shifted initial states hurt them most (Section~\ref{sec:results-robustness}). Plan-trained models have been reported to degrade when symbols are anonymized \citep{belcamino2026generalization}, but the setups differ: that model writes a whole plan, whereas ours emits one search step over runtime-supplied candidates. Training on BFWS traces raises FOLIO accuracy under all three observations (Section~\ref{sec:results-transfer}), a consistent gain that is not statistically significant, obtained from adapters that solve no planning task at that budget.

\paragraph{Limitations.}
\begin{itemize}
\item \emph{Stage.} All results are development-stage, and the frozen 45-task final evaluation has not been run.
\item \emph{Seeds.} Each main-grid cell uses one training seed, except two cells replicated over three seeds.
% Evidence: outputs/expanded-study/v1/seed-replication/analysis.json (two replicated cells, seeds 17/29/71); Section 4 accounting paragraph. Scoped to the main grid: the BFS large-corpus run used five training seeds (prior-evidence.json historical_bfs_stages[v8].metrics.per_seed 17/29/43/71/101); BFWS large-corpus run one seed (issue-59 L10-13).
\item \emph{Data cost.} The data-cost comparison is not matched: the large-corpus runs use different, easier panels and more epochs than the 512-record grid, and random-valid also solves the BFS panel. No BFS or BFWS corpus between 512 and 11,911 records was tested, so the smallest sufficient size is unknown.
% Evidence: issue-59-bfws-structural-gate.md L10-13 (two epochs); data/bfs_pilot_v6/ms-swift-process/manifest.json counts.train 12994 and prior-evidence.json historical_bfs_stages[v8] (15 tasks, random-valid 1.0); main grid one epoch per synthesis-v1/README.md.
% Evidence (smallest large corpus): docs/experiments/issue75/cost-panel-summary.json training_records bfs 11911, best_first_width 14225 (visual #75); v5-completion-verification.json bfs train_records 11911. Other BFS/BFWS corpora: 12,994 (BFS text), 47,780 (BFWS text); main grid 512.
\item \emph{Runtime.} The runtime supplies grounded candidates as text, so random-valid solves every additive task and success there measures valid execution, not frontier choice.
% Evidence: synthesis-v1/baseline-summary.csv random_valid 24/24 in every additive cell; Section 3 observation-types paragraph (candidates stay in text in every observation type).
\item \emph{Robustness.} Only the heuristic variants were tested on task variants, and we trained no plan-only baseline.
\item \emph{Transfer.} No transfer gain survives Holm correction over 36 comparisons.
\item \emph{Backbone.} We study one language-model family at 8B scale, and the second-backbone check (InternVL3.5-8B) uses a reduced 12-task panel.
% Evidence: synthesis-v1/README.md L125 (12/24 key-cell tasks) and L196-197 (reduced scope; InternVL3.5-8B shares the Qwen3-8B LLM family).
\item \emph{Appendix study.} The choice-frontier study covers only the two additive variants with scene-only observations.
% Evidence: Section 3 closing paragraph (appendix study: choice from rendered scenes alone, two additive variants only) and Appendix app:cf-contract (scene-only observation; issue-132-design.md sections 2 and 6).
\end{itemize}

\section{Conclusion}
\label{sec:conclusion}

% Paragraph purpose: Restate the question, give the development-stage answer (all four learnable at different data costs, text carries the signal, robust for the heuristic variants, a transfer hint), and end on the two open problems.
We asked whether a vision-language model can learn to execute classical search algorithms from their traces. On development panels it learns all four algorithms, at data costs that differ by over an order of magnitude. The learned execution rests on the textual serialization, holds up under task variations for the heuristic variants, and hints at transfer to logical reasoning. Search traces are thus a practical supervision target for planning research, alongside plans. Two problems remain open: learning BFS and BFWS from less data, and making the image channel carry the search decision.
