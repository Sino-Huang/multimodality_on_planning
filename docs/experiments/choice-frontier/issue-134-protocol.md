## R1 — submission-order-serial identity counterfactual (finding 49)

Finding 49 fix option (b): run the per-decision identity check on this runtime with heap serials
assigned in submission order; manuscript App B predicts the identity does *not* hold there.
Opposite predictions on the same pair set make this a killer test of the audit's sensitivity.

### Pair set

Exactly the 48 additive enumeration-contract pairs of `outputs/native-arms/v1/identity-audit.json`:
enumerated by the same rule as `identity_audit_stage` in `scripts/run_expanded_native_arms.py` —
every `(task directory, algorithm)` under
`outputs/expanded-study/v1/baseline/episodes/{text-state,visual-state,multimodal-state}/` with
algorithm starting `best_first_add` and both `random_valid` and `exact_reference` episodes present
(24 tasks x {best_first_add_greedy, best_first_add_w3}).

### Runtime and serial rules

Task binding is identical to the frozen baseline generation (`examples/planning_benchmark_slice/
visual_episode.py` + `expanded_baseline.py`): PDDL authority from the panel row's `task_path`,
`reference_costs` caps from `configs/experiments/expanded-study/final-panel.json`
(model-call limit = 2 x reference decisions, expansion limit = reference expansions), evaluation
seed 17 from `configs/experiments/expanded-study/baseline-protocol.json`. Policies are the frozen
control policies: `exact_reference` submits candidate row 0; `random_valid` submits a uniform row
from `random.Random(17)` per episode.

- **Executed rule** (`sorted_candidate_order`): the unmodified `BestFirstController` — heap serials
  assigned at `start_expansion` from the deterministic sorted candidate order.
- **Variant** (`submission_order`): a `BestFirstController` subclass identical in every other
  respect — same candidate generation, priorities, duplicate/reopen handling, budgets, state-ref
  assignment — except each target state's heap serial is assigned at `apply_operation` time, in the
  order candidates are submitted (first submission per target per expansion, one shared increasing
  counter across expansions).

### Validation gate (fails the run, not the artifact)

1. Every executed-rule re-run must reproduce its stored episode exactly: decision count, expansion
   count, goal flag, termination reason and the full `raw_output` sequence, for all 48 pairs x
   2 conditions x 3 modalities (counts) and the text-state store (raw outputs).
2. `exact_reference` submits in candidate order, so its trajectory is provably rule-invariant; the
   run asserts identical `exact_reference` trajectories under both rules for all 48 pairs.
   (Duplicates of an already-assigned target keep its first-assigned serial under both rules, and
   both rules are monotone in (expansion index, within-expansion order), so relative serial order —
   the only thing heap tie-breaking observes — is identical for candidate-order submission.)

### Metrics and pre-registered prediction

Per pair and serial rule, compare the `random_valid` and `exact_reference` runs: the sequence of
expanded-source canonical state ids per decision, decision/expansion counts, goal flag and
termination. A pair is **divergent** iff the expanded-source sequences differ at some decision
index (a length difference counts at the shorter length); the **first-divergence decision index**
is that index. Report identical and divergent pair counts for both rules and per-pair
goal/expansion/decision counts for both conditions under both rules.

Prediction (manuscript App B): under `submission_order`, random_valid and exact_reference diverge
on at least one decision in **most** pairs (> 24/48); under `sorted_candidate_order` they stay
identical 48/48.

## R2 — M4 task-cluster intervals (finding 60)

Finding 60: the M4 headline proportions are bare ratios over 132 decisions clustered in 18 episodes
and 9 tasks, with no interval. Both intervals below are **post-hoc diagnostics** — M4 carries
diagnostic status under the frozen #133 protocol, and this computation changes nothing to that
classification.

- Source: `outputs/choice-frontier/o4/metrics/all-episode-metrics.json` records with
  `arm == "learned_adapter"` and `teacher_decisions > 0` — the 18 stored #132 learned episodes
  (9 tasks x 2 algorithms, multiplier 2, seed 17). A gate asserts the pooled points equal
  `analysis.json` `arms.learned_adapter.m4_teacher_agreement` (23/132 = 0.1742 observed vs 0.2693
  chance; 72/132 = 0.5455 last label).
- Per task cluster (both algorithms pooled inside the cluster):
  - (a) `observed_minus_chance_agreement(t) = (sum teacher_agreements - sum teacher_chance_sum) / sum teacher_decisions`
  - (b) `last_label_minus_chance(t) = (sum selected_last_count - sum teacher_chance_sum) / sum teacher_decisions`
    (per-decision chance of the last label is 1/menu size, the same sum as the agreement chance).
- Interval: the zoo convention — nonparametric task-cluster bootstrap, the nine tasks of
  `choice-frontier-protocol-v1.json` `evaluation.membership` drawn with replacement in membership
  order, fixed seed 133, 10,000 draws, per-draw mean of the per-cluster statistic, 95% percentile
  interval with the zoo's `percentile` function (`scripts/analyze_choice_frontier_o4.py`).
