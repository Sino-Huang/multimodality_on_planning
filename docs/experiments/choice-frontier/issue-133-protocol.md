# O4 CPU comparator protocol — issue #133

Frozen before creation of any O4 comparator episode (2026-09-23 UTC). This is a new CPU-only, exploratory follow-up to #132, not an amendment of its frozen protocol or evidence. All nine tasks in the frozen final panel and both additive algorithm cells are repeated measures of nine task clusters. No GPU run is authorized by this protocol; #133 explicitly excludes it.

## Arms and shared runtime

Retain all 144 #132 episodes unchanged: learned_adapter and pretrained_base (one seed per cell), random_valid (five seeds per cell), exact_reference (one seed per cell). New CPU selectors: **bfs-order** (minimum live frontier `g`, then earliest generation serial) and **novelty-first selection** (minimum width-1 unseen-atom novelty score, then width-2 unseen-pair novelty score, then earliest generation serial; novelty features are positive PDDL state atoms; seen feature sets advance only when a state is expanded, including the initial expansion). Novelty is selection only, NOT BFWS novelty pruning. Also run **worst-first** negative control (maximum additive priority, then earliest generation serial). Each comparator runs both additive settings (best_first_add_greedy, best_first_add_w3) on all nine tasks, seed 17, under the existing ChoiceFrontierModelSession menu/choice/action/budget contract; reference baselines use existing exact_reference, random_valid. Comparator labels are mapped back to the menu binding; all candidates still enter through the additive BestFirstController admission path, even for bfs-order and novelty-first. Thus frontier admission, duplicate detection, h_add calculation, reopen policy, serial ordering and scene/menu contract stay additive; these selectors are **not** the frozen native BFS or BFWS algorithms. Record both comparator outcomes and the panel's frozen native algorithm-family reference costs (bfs, best_first_width, best_first_add_greedy, best_first_add_w3) separately, never conflating the two contracts. Selectors read trusted g/h, state atoms and serial; the VLM receives only visual scenes. This oracle-access asymmetry precludes an information-matched learned-vs-rule causal claim.

The frozen cap for all primary episodes is **2 × additive exact-reference expansions** per task/algorithm, simultaneously decision and expansion cap; never rescale to the comparator's own reference cost. Additional CPU-only random_valid and all three new rule selectors run at **3× and 4×** additive reference expansions on every task/algorithm, five original random seeds for random_valid, seed 17 for deterministic selectors. Original 2× episodes are unchanged. Report every arm including failures and missingness. Re-run each new episode with an independently constructed PDDL authority through `replay_choice_episode`, checking all menus, decisions, admissions and result dictionaries. Preserve raw episodes and a coverage/replay manifest.

## Pre-registered metrics and claims

Budget multipliers for primary M1: **1, 1.25, 1.5, 1.75, 2**. For a prefix-valid complete episode, solve at m iff its first goal-selection event occurs by decision cap `floor(m R_t)` and preceding expansions ≤ `floor(m R_t)`, where R_t is additive exact expansions; unsolved 2× runs are failures at all m. Apply the same prefix truncation to every arm. M1 is trapezoidal AUC of solve fractions over m, divided by the width 1, equal task weighting, equal algorithm weighting within task, random seeds averaged within cell. Primary uncertainty: nonparametric task-cluster bootstrap, nine tasks drawn with replacement, fixed seed 133, 10,000 draws. Repeated algorithms and random seeds always stay inside their task cluster.

M2: expansion overhead ρ=X/R_t. Report geometric mean only on co-solved paired cells, explicitly survivor-conditioned. Also report censored expansion overhead: failures at a given budget are right-censored at that budget, never assigned fictitious successful X; provide solved fraction and mean observed min(X, cap)/R_t alongside censored counts. M3: cost suboptimality κ=C/C*, where C is the number of transitions along the selected goal state's trusted predecessor chain (unit-cost PDDL), C* from **one offline CPU shortest-plan planner computation per distinct task**, reused across both additive cells and every arm. Unsolved κ is undefined (never imputed); report solved coverage and co-solved paired κ. M4: on-policy teacher agreement over decisions with at least two live choices, teacher being the current additive heap head; expected chance is decision-weighted mean 1/K, report observed minus chance and full selected-label position histogram, separately by arm. M5: D={task: 0<p_random,task<1}, where p_random is the mean 2× solve indicator over the two algorithms and five fixed random seeds (controls ONLY); report all metrics on D descriptively, including if D is tiny. M1–M5 on stored #132 episodes are **post-hoc exploratory**, not confirmatory, and the 2× cap prevents extrapolation of their curves beyond m=2.

Claim unit: Pareto position/dominance across M1 AUC (higher), M2 co-solved expansion overhead (lower; conditional), M3 co-solved κ (lower; conditional). A positive dominance claim requires weak superiority on all three paired task-cluster measures and strict superiority on at least one; comparisons learned vs each of bfs-order, novelty-first, worst-first, exact_reference and random_valid must all be reported. For any inferential positive comparison, use paired task-cluster bootstrap one-sided p values and Holm step-down correction across **five comparators × three metrics = 15 tests**; undefined or uninformative co-solved contrasts prohibit positive dominance, not count as wins. M4 and M5 are diagnostics, not opportunistic additional confirmatory tests; no equivalence or generalized negative capability claim from non-significance. Include all per-task outcomes and unadjusted/adjusted results. Any added selector, changed tie-break or changed metric after the first episode requires a dated, explicit protocol amendment and cannot inherit this preregistration. #123 0/36 on BFS is an old enumeration-contract algorithm confound, never an O4 comparator result.
