# Scene-only matched study

The user approved scene-only initial and current states, object labels, separate
static-context and source-goal constraint pages, and agent-executed training.
Study v4 retains the v3 candidate pool and selected Storage 760000, Blocksworld
730060 and Ferry 780004 tasks. Source records, targets, splits, ordering, shared
Search Memory, model/processor revision and training settings are unchanged.

Preparation covers all 2,156 selected records, 81 tasks and 1,588 required scene
states, including the full 152-state held-out closure. Native 1536px scenes are
rasterized from retained supplied-plan VFGs. Original 128px scenes and all traces
remain in place. Object names use 24px text with deterministic non-overlapping
placement and leader lines. The robot has a contrasting silhouette. Static
pages omit initial dynamic facts; those are conveyed by the initial scene.
Goal pages retain the source constraints without inventing a solved state.
Both initial/current scenes and the complete context/goal set accompany each
visual or multimodal call. Text uses the unchanged symbolic projection;
multimodal pairs that projection with the same scenes used by visual.

The native view manifest binds every selected record to its task, split, state
and ordered page roles, and every state image to a retained VFG stage. All image
sizes are measured using the actual frozen processor; complete prefixes and
supervised inputs are checked. The loss mask uses actual image dimensions and
supervises the identical assistant-target tokens across modalities. The shared
per-process pixel cache remains bounded to 64 MiB.

The four completed v3 text adapters are retained only after exact input/target
and setting checks. The remaining eight cells train fresh adapters. No #75/#76
or curriculum checkpoints are substituted. Native resumes retain a concrete
input/settings binding, and verification checks final update 16, finite logged
losses/gradients, diagnostics at 5/10, and trained-adapter/base isolation.

All stages share the original v2 ledger and process lock. Allocations remain
3,600 seconds qualification, 18,000 training/development, and 21,600 evaluation;
prior spending counts. Native qualification reserves 15 seconds for shutdown,
with the tested hard worker/process-group cutoff still active. Training and
evaluation retain their 120-second reserves. No stage borrowing or budget reset
is introduced.

GPU qualification reuses unchanged text evidence. For each new image modality,
the four algorithm-family scalar/mixed/repeated checks are divided across the
two GPUs. Each GPU independently runs forced 384-token timing on the actual final
input that dominates all selected token lengths and image shapes/counts, plus a
disposable lr=0 backward/optimizer/save probe on the largest supervised source
input. The input-envelope condition is checked rather than assumed. Reports
retain exact cases and per-device costs. Admission accounts for spent text
training and estimates only the remaining cells, with the existing 1.25 factor.

CPU preparation and focused tests have passed; see v4-preparation.json. Native
visual qualification passed on both A100s, covering all four algorithm families.
Multimodal qualification stopped at the cumulative qualification cutoff; see
v4-qualification-stop.json. An earlier native attempt exposed a fixed-page
assumption in inference input counting; the actual-dimension correction has a
CPU regression test and was used by the resumed GPU attempt. Both attempts
remain charged to the shared ledger. No native visual or multimodal adapter
has trained, and overall model readiness remains false. A prospective budget
revision has been requested but is not approved. The four completed text
adapters remain available; final held-out evaluation has not run.
The CLI defaults to study-v4.json and exposes prepare/qualify/train/decide/
evaluate/verify, dry-runs and resumable execution with progress heartbeats.

This is scene-only state input within a shared symbolic planning interface,
not image-only end-to-end planning. Candidate information remains available in
all conditions. The three small held-out tasks support a descriptive comparison,
not broad generalization or training-seed variance claims. Storage has no rows
in these particular training subsets; retain that limitation.
