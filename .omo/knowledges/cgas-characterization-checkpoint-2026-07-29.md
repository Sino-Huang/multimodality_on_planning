# CGAS Characterization Checkpoint Publication

Date: 2026-07-29

- `cgas_characterization_checkpoint` exposes typed checkpoint build, load, and no-replace publication operations. `cgas_characterization_checkpoint_contracts` owns the immutable envelope and canonical filename range so the I/O module remains below 250 pure lines.
- Private checkpoint staging is caller-supplied and must be a canonical, non-symlink, owner-controlled mode-0700 root on the same filesystem. It must be strictly external to the checkpoint root: equality, either ancestor/descendant relationship, and descriptor-identical aliases are rejected before temporary creation. This permits descriptor-rooted cross-directory `renameat2(RENAME_NOREPLACE)` while ensuring failed pre-rename data never appears in the checkpoint tree.
- The primary durability sequence is write-loop, file fsync, identity check, `renameat2(RENAME_NOREPLACE)`, published bytes and identity check, private-parent fsync, destination-parent fsync. Do not substitute `os.rename`, `os.replace`, or a check-then-rename fallback.
- When `renameat2` rejects only no-replace flags with `ENOSYS`, `EINVAL`, or `EOPNOTSUPP`, use descriptor-rooted `linkat` from the still-fsynced private name. Verify device/inode/owner/mode/bytes and link count 2, fsync the destination parent, descriptor-unlink the private name, verify published link count 1, then fsync the private parent. Report every post-link failure as durability-indeterminate; report the private path only while that name remains.
- `renameat2_noreplace_linkat_v1` is a policy field in the canonical run contract. A protocol revision changes the run fingerprint and thereby checkpoint envelope bindings; a node-local primary-versus-fallback choice does not alter the canonical checkpoint bytes.
- `load_checkpoint()` must check its pinned descriptor before and after reading: regular type, mode 0600, effective owner, and link count exactly 1. This makes a published linkat destination acceptable after private unlink and rejects any later hard link with the stable `checkpoint must be owner regular mode 0600 single-link` rule.
- The publication AST regression forbids ordinary `rename`, `replace`, and `exists` call sites. It requires exactly one injected `rename_operation` primary call, exactly one injected `link_operation` fallback call, and the explicit `renameat2`/`linkat` filesystem-wrapper imports.
- The supported owner-review lifecycle uses one command-wide lock and one writer. The removed foreign-admission and checkpoint-descriptor ledger are not part of the product contract.
- Runner establishes raw regular-leaf pins before the work-verifier callback, allowing malformed regular leaves to reach verifier validation while blocking symlinks and special entries up front. Immediately after callback return it requires the original namespace, retained inode metadata, raw bytes, and verifier-approved canonical bytes/envelopes to agree; callback-time replacement, addition, removal, and content mutation are `checkpoint_state_drift` before a characterizer call.
- `cgas_characterization_contract_pins` retains a no-follow work-directory plus `run-contract.json` descriptor across verifier and every row boundary. It validates owner mode `0600`, link count one, byte cap, canonical bytes, namespace identity, and reread bytes; the runner maps any failure to `run_contract_drift`. Repository-local GPFS QA on 2026-07-29 performed 20 same-byte unlink/recreate substitutions, detected drift, and restored the original FD count after context cleanup.
