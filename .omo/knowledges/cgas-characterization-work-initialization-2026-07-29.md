# CGAS Characterization Work Initialization

- `scripts/phase3/cgas_characterization_work.py` uses `.initializing` as a durable incomplete-state marker. It is fsynced in the work root and parent immediately after creation; removal is likewise fsynced in both directories after payload durability.
- Interrupted initialization is intentionally not repaired or deleted. Root inspection rejects every tree except `{checkpoints, run-contract.json}` and requires the expected canonical contract bytes.
- Runner fresh/shard/resume paths translate `WorkRootError` into `RunnerError`, preserving stable reasons before verifier or characterizer execution.
- Verifier checkpoint-root inspection calls `read_initialized_contract()` first, so partial work roots fail with the same stable reason.
- Fresh and require guards must never use `Path.exists()` for final or work roots. `_root_entry_statuses()` opens their parent with `O_NOFOLLOW` and stats each final name with `follow_symlinks=False`; dangling symlinks are therefore existing unsafe entries. Initialization keeps parent and root descriptors open through marker, checkpoint, contract, and marker-removal durability operations, then verifies the pinned root device/inode/owner/mode against both the open descriptor and final parent entry. A swapped public root therefore fails as indeterminate and cannot receive redirected writes.
- `MAX_RUN_CONTRACT_BYTES` is the shared 2 MiB cap in `cgas_characterization_contract.py`, with `RUN_CONTRACT_SIZE_POLICY_VERSION` included in generated contracts. Work-root contract reads validate pinned descriptor type/owner/mode/nlink and size before pread, use 64 KiB chunks, and compare descriptor identity/size after reading.
- `CheckpointEntry` pins name/device/inode/size after verifier validation. Runner derives completed names from that snapshot, descriptor-rescans immediately before each characterizer, and permits only its own exact publication transition. Any dangling, special, malformed, newly added, or replaced checkpoint leaf causes `checkpoint_state_drift`.
- New work and checkpoint directories are descriptor-fchmoded to exact `0700`, owner/type verified, and child/parent fsynced immediately after creation. This clears inherited SGID bits. Supplied private roots remain strict inputs because runner does not create them.
- `RunContractSnapshot` is the canonical no-follow contract loader result, carrying bytes and device/inode/size. Runner pins it before verifier execution and requires unchanged identity, bytes, and builder fingerprint immediately before and after every characterizer call; substitutions fail as `run_contract_drift` before checkpoint publication.
- Validation on 2026-07-29: the focused pinned-root suite passed 67 runner/work/verifier/checkpoint tests, including marker/checkpoint/contract/file-sync root substitution races with an empty outside target. Basedpyright 0 errors and compileall passed. The full Phase 3 collection is independently blocked by output-layout import failures.
